# TRIALUM 1.5.6 — Social Friends, Skills & Shared Playground

Status: **approved scope / staged implementation**, 2026-11-08. This document is the implementation contract, NOT a claim that 1.5.6 gameplay is implemented. Base version: 1.5.5 in main. Do not release a new APK or merge a production-ready claim before all gates pass.

## Product promises (non-negotiable)

- Offline solo play remains fully playable. No forced account, online connection, cloud backup, subscription or purchase.
- **NO third-party ads, SDKs for advertising, ad identifiers, user tracking, data brokers or sale of data.** Internal game update/news announcements may appear in-game, but do not track impressions.
- Every eventual purchasable gameplay advantage must also be unlockable by free normal play, with a transparent and reasonable progression path; paid items are optional accelerators, not exclusive power. No paywall over multiplayer basics, game saves or safety.
- No payments in 1.5.6. Google Play Billing, server-side purchase verification, refund/replay controls, offer disclosures and an abuse audit are a later separate phase; paid rewards cannot be trusted from clients.
- Protect local saves; backwards-compatible migration and JSON export are required.

## A — Fix broken friend invitations, build honest UX

### Current verified fault
js/peer.js uses manual three-message WebRTC offer -> answer -> finish. parse(input,'offer') throws 'Внеси покана од ТРИАЛУМ' when code kind/description is mismatched; a correctly pasted answer or corrupted share is rejected. app.js uses big JSON SDP textareas. Also STUN alone doesn't ensure connectivity across NATs; sharing does not deliver pairing state.

### Final UX
One screen: [Add friend] -> [Nearby] or [Share invite]. Receiving invite opens app directly and offers [Accept] or [Decline]; owner is notified. Maximum two explicit interactions per side in normal path, no raw SDP text shown. Advanced diagnostics hidden under developer section. The Android Sharesheet is used only to distribute the deep link; native Nearby Connections is optional for short-range discovery with explicit permission and mutual verification.

### Protocol
- Server-issued unpredictable single-use invite tokens: 128+ bits entropy, short TTL (15 min), bounded attempts, hashed at rest, bound to inviter and session; invite cannot contain authentication tokens or private pet data. Recipient authenticates separately.
- HTTPS app link/deep link, validate domain, scheme, size, expiry, reject replay and untrusted intents; users see the inviter's pseudonym and confirmation.
- Friends are durable only with bilateral consent; block, remove and revoke are first-class actions.
- For no server/internet: explain 'online features unavailable' rather than showing a false successful connection. Nearby direct play can still work independently if both devices are physically close.
- Device key credentials or strong installation credentials are stored in protected Android storage. API bearer/session credentials MUST NOT be committed, logged or copied in shared backups.
- Do not make Google Play Games sign-in mandatory.

## B — Skill system repair and useful interaction

Six skills: wave, spin, leap, symbols, logic, dialogue. Training must dispatch an immediately visible performance without using another daily action. Replay is free, accessible from pet card and world on tap; no automatic loss of learned levels. All six render in classic and evolved art paths, including transitional morphs and low-motion mode.

| Skill | Visible behavior | Interaction | Progression |
| --- | --- | --- | --- |
| Wave | Articulated fin/arm, eye focus and friendly expression | Tap to greet another pet | More expressive timing and social response |
| Spin | Full turn, directional trail, settle pose | Spin in place or on toy | More controlled/longer choreographies |
| Leap | Height arc + grounded shadow, squash/landing/splash | Obstacles, trampoline, playground | Precision and height |
| Symbols | Floating marks with anticipation/reaction | Match simple symbol sequences | More patterns, no hidden answer purchase |
| Logic | Animated problem and thinking pose | Short accessible puzzle | More varied patterns and feedback |
| Dialogue | Lip/face/gesture + speech bubble | Short fictional pet exchanges | Personality variants; optional opt-in LLM remains separate |

Training level is not merely a counter: unlock an action every level and demonstrate upgraded animation at skill milestones. XP: server/engine verified, daily caps, no grinding by repeated rapid taps, clear balance; locally offline progression remains player-owned. Accessibility: reduced motion, high contrast, no mandatory timed puzzle.

## C — Solo Playground

- Unlock at **pet evolution level 15** and **research lab level 4** for an existing or new world. Retroactive unlock; no new save required.
- A basic free playground of 1 shared *local* plot (for the owner's pets) with a sandbox and seesaw already open. Slide unlock at level 20, pool at 25, obstacle course at 35, trampoline at 45; exact numbers and resource costs configurable in a single game data table.
- When user opens playground: visible landscape, toy hotspots, animation preview and task controls. [Play] is immediate, with choice of pet and toy; skill-specific animations and interactions occur in real time.
- Per-pet energy/comfort and earned skill XP; visible progress, max skill levels, diminishing returns/caps. Sandbox practices symbols, seesaw cooperation and balance, slide leap, pool swim/splash, obstacle course logic & leap, trampoline leap/spin; all with safety/feel-good feedback and no animal distress.
- Guest animals do not become property of host; host may not rename, sell or transfer visitors.
- Offline completion is retained locally. Synchronization happens later with conflict resolution and no unearned server rewards.

## D — Friend visits & shared Playground

- After pairing, send pet to (1) friend's habitat or (2) mutual playground. Sender chooses destination; receiver may approve/reject. Explicit expiry and automatic return; no pet deletion on timeout or disconnect.
- **Shared playground membership is a consent-based small group**: joining one friend does NOT silently merge all of each person's other friends. Owner/admin roles with revocable invitations, block removal, member list and activity log.
- Playground access is inherited by an invited friend even if their personal unlock level is lower: they can visit and play in the shared location, but their own solo playground unlock remains unchanged. Prevent this from accidentally unlocking unrelated species/skills or spending locked resources.
- Space and toys upgraded cooperatively using an auditable shared contribution ledger and atomic server transactions. No owner can erase others' earned contributions without visible confirmation and an exit policy.
- Real-time authoritative action events from the social server, e.g. pet_start_action(id,toy,action,timestamp,sequence), all phones animate deterministically; server snapshot + sequence reconciliation on reconnect. Do NOT stream video frames/audio/chat histories. Throttle event rates and account for clock skew.
- Network loss: last safe snapshot, graceful stop, replay/return on reconnect, no duplicate credits; offline solo playground always usable.

## E — Minimal friend communication and Android notifications

- No traditional public chat channels or presence stalking. Direct event cards: invite received, visitor pending, visit arrived/ended, shared upgrade, short message.
- Initial flow: preset phrases plus optional short text (max 120 visible characters), rate limits, spam filter, block/report, per-friend mute, no push preview of private message by default. A future safety/legal review is required before free text is enabled for minors.
- Retention: undelivered message TTL <= 7 days, accepted messages locally optional; delete-on-demand and no indefinite server transcript. Store text encrypted at rest where supported; never claim end-to-end encryption without shipping it.
- Android push opt-in: app uses FCM registration token only to route transactional notifications; token changes handled and deleted on logout/removal; notification permission Android 13+. Generic payload includes event reference only, not free text or pet private statistics. User can opt out; polling when app opens must still work.
- Real-time WS is for foreground visits; FCM covers background delivery. Do not depend on background WebSocket to wake Android.

## F — UI/QA/release gates

UI targets: readable pet cards, shared playground dashboard, distinct status for 'online', 'awaiting approval', 'offline', skill animations, low-motion, landscape, portrait, localization, accessibility. No dark-pattern FOMO, nagging, infinite popups or aggressive monetization.

Gates:
1. Domain tests for unlocks, visitor authorization, shared contribution atomicity, replay/idempotency and anti-spam.
2. Two-Android handshake tests on same Wi-Fi and different networks, Android Sharesheet/app link flow, invalid/expired/replayed invites, block/report.
3. Reconnect, 2+ users animating one event, offline fallback, out-of-order WS, clock skew.
4. Visual verification of six skill actions on classic/2.5D forms, sandbox/seesaw/slide/pool, sound and reduced-motion options.
5. No user save reset, battery/data-use budget on Galaxy-class phone, 17 language control and notification permission test.
6. Automated Node+Android CI, external network security test, privacy audit, backed-up DB restore rehearsal, owner manual approval.
7. Only then candidate APK/AAB and release notes. One subphase at a time; no passing phase by self-declaration.
