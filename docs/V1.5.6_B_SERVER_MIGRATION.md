# TRIALUM 1.5.6-B — Ubuntu NAS-safe migration (EXISTING PostgreSQL volume)

**Do not execute automatically.** Current host maps Readarr's 8787 conflict to a free host port, e.g. `127.0.0.1:8687 -> container 8787`. Preserve the user's chosen `TRIALUM_HOST_PORT`, WireGuard, Webmin, NAS and other containers. Do not use `docker compose down -v`.

## Preconditions
- 1.5.6-B branch is reviewed and merged into main; Ubuntu's `/opt/trialum/server` has been updated through a trusted GitHub Desktop -> server copy. Verify that local `server/Dockerfile` is not overwritten by older source: corrected upstream Dockerfile runs as `node` and owns readable files.
- PostgreSQL health succeeds: `curl -fsS http://127.0.0.1:8687/healthz`. Social endpoints remain disabled by default.
- Reserve sufficient disk/memory for NAS workloads, use WireGuard to administer.
- Private `.env` must NOT go through Git or be pasted in chat.

## Add new application role without affecting existing two passwords
1. In `/opt/trialum/server/.env`, ensure `TRIALUM_HOST_PORT=8687` (or actual free port), keep the existing PG and health passwords unchanged, append:
```ini
TRIALUM_SOCIAL_ENABLED=false
TRIALUM_APP_PASSWORD=CHOOSE_A_NEW_UNIQUE_RANDOM_64_HEX_VALUE
```
Use `openssl rand -hex 32` for the new secret and paste it directly into the private editor. Never paste output in chat or shell history. Ensure `chmod 600 .env`.
2. The new SQL script is mounted read-only at `/docker-entrypoint-initdb.d/003_social_role.sh`. Recreate **only affected containers without deleting volumes**:
```bash
cd /opt/trialum/server
docker compose config --quiet
docker compose up -d --build
docker compose ps
```
3. A PostgreSQL volume already initialized will **NOT** run init scripts automatically. Apply the idempotent migration on the existing DB:
```bash
docker compose exec -T trialum-db sh /docker-entrypoint-initdb.d/003_social_role.sh
docker compose exec -T trialum-db psql -U trialum -d trialum_social -tAc "SELECT EXISTS(SELECT 1 FROM pg_roles WHERE rolname='trialum_app');"
docker compose exec -T trialum-db psql -U trialum -d trialum_social -tAc "SELECT to_regclass('public.friend_blocks') IS NOT NULL;"
```
Both SQL checks should return `t`.
4. Check health and confirm networking stays disabled:
```bash
curl -fsS http://127.0.0.1:8687/healthz
curl -fsS http://127.0.0.1:8687/v1/meta
```
The metadata should include `"liveSocialEnabled":false`. Test endpoints remain private. No Tailscale Funnel or router port forwarding yet.

## Local-only B API trial after protocol/security review
Only when desired, set `TRIALUM_SOCIAL_ENABLED=true` in private .env and recreate just API:
```bash
docker compose up -d --no-deps --force-recreate trialum-api
curl -fsS http://127.0.0.1:8687/v1/meta
```
`"liveSocialEnabled":true` confirms service activation; it does NOT prove public HTTPS availability or two-device UX. Keep host binding `127.0.0.1`, no router changes. If you want to turn off B: `TRIALUM_SOCIAL_ENABLED=false` and recreate the API. Never `down -v`.

## Important limits
- First-release rate limiting is in process memory, not cross-replica; do not expose open registration publicly until reverse proxy rate limiting and abuse controls are reviewed.
- PostgreSQL backups may contain pseudonymous user records; restrict file permissions and set retention/deletion.
- Rotating `TRIALUM_APP_PASSWORD` requires ALTER ROLE in DB AND matching .env, not .env alone. Previous health password was once exposed via Docker inspect; it must be rotated as already handled separately. Docker inspect prints `DATABASE_URL`; do not post it again.
- Tailscale Funnel is a **public endpoint**, unlike private router WireGuard. It must not expose this beta until security gate. Future owned domain/cloud move is separate.
