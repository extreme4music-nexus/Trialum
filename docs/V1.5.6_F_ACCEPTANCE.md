## High-priority findings and disposition

1. **CRITICAL UNTIL REMEDIATED: Public plain HTTP social API.** The owner reported `http://dedopero.servegame.com:8787` publicly reachable. Do not send login/installation Bearer secrets or personal messages there. Issue a trusted certificate, route `443` through Caddy or existing reverse proxy to the local-only API, close the public `8787` forward. [Full operator guide](V1.5.6_F_HTTPS_DEPLOYMENT.md). The Android release code strictly accepts HTTPS only.
2. **HIGH: Existing server database migrations are not proven.** SQL 003–005 are manual for pre-existing Docker volumes, and a separately verified backup/restore rehearsal is mandatory. Never `docker compose down -v` or reinitialize the production volume.
3. **HIGH: No physical two-phone / device FCM acceptance yet.** GitHub Actions cannot prove Bluetooth/Nearby comparison, push permissions, background power/FCM receipt or real-world touch/animation performance.
4. **MEDIUM: Custom URL-scheme invite interception.** The 15-minute one-use invite token is not an account bearer credential, but `trialum://` is not a verified Android App Link. For public Play Store release, configure verified HTTPS Android App Links and domain `.well-known/assetlinks.json` for the final signing certificate. Do not claim this is completed.
5. **MEDIUM: Development signing keys may change between GitHub Actions runs.** Preserve a stable authorized debug/test keystore if upgrading over existing APKs, and test JSON export/import **before uninstalling** any existing installation. Never place signing credentials in source.
6. **MEDIUM: Safety of free-form messaging.** Explicitly keep `TRIALUM_FREE_TEXT_ENABLED=false`. The minimal link/phone filter alone is not child-safety moderation. Enforce age-appropriate rules before considering free text and build robust abuse/report workflows.
7. **MEDIUM: Firebase external processing and privacy notices.** Even without in-game tracking, Google's FCM handles device push identifiers. Describe this truthfully in privacy disclosures and Data Safety. Real user opt-in, rotation and deletion require two-device evidence.
8. **MEDIUM: Server HTTP ingress abuse / network hardening.** Limit private test identities; review reverse-proxy ingress, application/auth rate limits, backups, token rotation and server request limits before allowing arbitrary public players.
9. **LOW: 17-language availability does not imply native-speaker translation quality.** Run UI and accessibility checks, contrast, talkback, enlarged fonts and RTL review; do not claim full language QA simply from locale loading.

## Real operator/device test script (record PASS/FAIL and screenshots without tokens)

1. Save/export a real existing world and **verify its import** in a separate test installation. Confirm identical pet names, XP, habitats, creativity, game-day, coins, tricks, logs, species, and solo playground.
2. On two real Android phones (at least one Samsung Galaxy A55), test fresh install and upgrade with **same signature**, first start offline, all tabs, pet blink/wink, six skills, sandbox/seesaw, earned slide/pool, daily cap, landscape/portrait and reduced motion.
3. On server, `/healthz` and `/v1/meta` over **trusted public HTTPS only**; test from cellular network (Wi-Fi off). No HTTP fallback. Confirm old public 8787 unreachable and Webmin/PostgreSQL not exposed.
4. Friend A sends short-lived invite to B; B explicitly approves, both see same friendship; expired/replayed, blocked, offline and nearby declined cases reject; compare matching authentication digits **on both screens**.
5. A invites B to shared playground; B explicitly accepts; third uninvited phone sees neither snapshots nor pet data. Validate authorized visit approve/reject, revocation, sharing offline sync and earned group actions (no duplicate XP/points).
6. E: preset messages, duplicate safe retries, report, mute, one-side delete, both-side delete, block purge, 7-day retention, no free text; verify no account bearer or encrypted key in JSON export.
7. If Firebase is configured, enable push *by pressing the in-app button*: check Android runtime permission, data-only generic banner, background/cold start, revoked permission, token rotation, app restarts, opt-out while offline, and no further notification after deletion.
8. Check no crashes or pathological memory/battery use during >30 minutes of gameplay; TalkBack, font scaling, accessibility focus and RTL; confirm development logs do not expose secrets.
9. Ensure feature flags are OFF when gate tests end or operator explicitly authorizes scoped staging. Capture SHA-256 of tested APK, GitHub Actions run URL and commit SHA. Never modify the known-good world data before backup.
