```sh

curl -fsS http://127.0.0.1:8687/healthz || :
```

Identify exactly which **local** loopback port returns `{"status":"ok","db":"connected"}` (it might be 8687 per earlier Ubuntu setup; 8787 is the container port and the user reports it externally). Never replace another service's listener, especially Readarr, Webmin or WordPress. If ports 80 or 443 are already occupied by a web server, use the existing reverse proxy's HTTPS virtual host instead of installing another conflicting listener.

## DNS and firewall

- No-IP DNS A record for `dedopero.servegame.com` must point to your current public IPv4; maintain your existing DDNS update client. Check with `dig +short dedopero.servegame.com A`. Verify that no stale AAAA record points to a different host.
- Configure the router **only** to forward **TCP 80 and TCP 443** to the Ubuntu host running Caddy. Do not forward 8687, 8787, PostgreSQL 5432, WireGuard admin, Webmin or NAS fileshares. Check Ubuntu UFW/nftables permits 80/443 to Caddy, no broad reconfiguration.
- To avoid interrupting current users, configure HTTPS **first**, verify off-network, then remove existing WAN port 8787 forward immediately. While 8787 remains public, do not send real social credentials.
- If ISP CGNAT prevents inbound 80/443, or the 80/443 host belongs to another service, **stop here** and use the existing managed web proxy or a separately scoped HTTPS tunnel. Do not alter WireGuard/production web traffic impulsively.

## Free automatic HTTPS with Caddy (only if ports 80/443 are free)

Official installation: https://caddyserver.com/docs/install

Caddy's Ubuntu package installation commands from its official documentation:

```sh
sudo apt install --yes debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo chmod o+r /usr/share/keyrings/caddy-stable-archive-keyring.gpg /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install caddy
```

**Note:** the Caddy package starts a Caddy systemd service. First confirm 80/443 are not in use; stop if they are. Copy `deploy/https/Caddyfile` to `/etc/caddy/Caddyfile` **after** making a backup of the existing file and checking the upstream local port:

```sh
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.before-trialum
# Copy the reviewed repo file deploy/https/Caddyfile to /etc/caddy/Caddyfile.
# If API responds locally on 8787, replace reverse_proxy 127.0.0.1:8687 with :8787.
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
sudo systemctl status caddy --no-pager
```

Recommended Caddyfile snippet (**real file** at `deploy/https/Caddyfile`):

```caddyfile
dedopero.servegame.com {
    @trialum {
        path /v1/* /healthz /invite
    }
    handle @trialum {
        reverse_proxy 127.0.0.1:8687
    }
    handle {
        respond "Not found" 404
    }
}
```

Caddy gets/renews publicly trusted TLS certificates automatically when the DNS resolves and external TCP 80/443 reaches it. It proxies WebSocket upgrades automatically. Do not enable `tls_insecure_skip_verify`; clients must use a valid publicly trusted HTTPS certificate.

Only after HTTPS is verified, go to GitHub repository **Settings → Secrets and variables → Actions → Variables** and set the *public* variable:


Do not append `:8787`, `/v1` or trailing slash. Run Android workflow on `main` and download that new **RC debug APK**.
