# LW-C v32 — optional mini LLM pet dialogue with ephemeral private-room relay

**Owner decision 2026-11-12:** the owner explicitly marked all three signed v31 / LW-C real-time playground APKs a definitive **physical OWNER PASS**. Preserve those binaries and their signer identities. The next requested addition is an *optional* smallest (SmolLM2-135M) on-device model taking over one pet's spoken replies while a playground is visible. Non-AI participants must retain the existing simulated autonomous play.

**Status:** implementation candidate on a separate feature branch, **NOT an owner-tested APK, NOT deployed to the home Debian server, NOT a public Play release**. A source CI PASS must not be relabeled physical owner acceptance.

## Client contract
- Unchanged eligibility: evolved species Synapso or later (species >=4), pet level >=22 and laboratory >=6; the user must have explicitly downloaded and verified the existing ~94 MB mini GGUF model. Never auto-download.
- Per-pet, per-place opt-ins: `pet.playgroundAiLocal` (offline local only) and `pet.playgroundAiShared` (private shared room). These simple booleans survive JSON backup/restore; a new shared toggle requires an explicit explanation that visible lines reach confirmed room participants and are **not** end-to-end encrypted.
- Local app uses the simulated companion's current utterance (or an occasional independent thought) as bounded context for the mini model and replaces the *visible* caption. **Only the first short sentence** (max 17 whitespace-separated words / 112 characters, Android generation capped to 48 tokens) may appear or be relayed. It **does not** change actions, skill/XP caps, journal, rewards, growth, pet ownership, AI manual-chat history, or room membership.
- Shared app processes authenticated `pet_speech` WebSocket messages; a user with an active mini model can generate a new short answer. A user without the model continues receiving and occasionally relaying existing rule-driven lines. No one needs to install a model to play with an AI-owning friend.
- **Foreground only:** the respective playground tab must remain visible; tab changes, background, restore and room switches cancel/drop pending AI completions. Native generation is best-effort cancelled (synchronous GGUF inference might take a moment to unwind); no background scheduling or display of a late reply.
- **Contextual memory, not a transcript (owner follow-up, 2026-11-12):** the pet's local JSON keeps a small daily aggregate of theme IDs, day, place, limited cosmetic companion names and a bounded interaction count when its AI is opted in and visible. No verbatim incoming/outgoing speech, freeform user text, server credentials or room identifiers are stored. At most 45 days / 60 daily aggregates per pet; the player may clear memories independently of XP or journal. The manual mini chat (and advanced opt-in chat for an eligible evolved pet) receives the matching contextual tags, prioritizing **yesterday** when asked ‘што разговаравте вчера?’. If nothing was recorded for that day the model is instructed to say it does not recall, not invent a story. Brief simulation in the background does **not** create fictional AI memories.
- Repetition is bounded locally (roughly 24 seconds per model attempt) and at the server (10 seconds per account/room); no autoplay XP or server currency.

## Server contract
- Reuse the existing authenticated WSS `/v1/social/live`, existing private PostgreSQL `pet_presence` leases, room membership/friendship/block checks, and HTTPS origin restriction.
- `pet_speech` is opt-in and **disabled by default** via `TRIALUM_PLAYGROUND_AI_ENABLED=false` in `server/.env`. It also requires existing social, shared and presence capabilities. Advertise availability to authenticated clients through `/v1/shared/status`.
- Sender must have an authorized room subscription, a live and exact `installation_id + room_id + pet_ref + session_id` lease. Server supplies the speaker name from the verified stored cosmetic pet profile, not caller-supplied speaker or XP.
- Recipients must be authenticated, subscribed, actually present in the same room, not blocked and remain room-authorized. No cross-room notifications or offline delivery. Bounded short text only (160 chars, no URLs, emails, control chars, long phone numbers); no transcripts, new SQL tables, storage, push, analytics or extra exposed port.
- No inference on the server and no server-recognized AI/XP authority. **The server cannot attest that an authorized client really used a model instead of composing a phrase**; safety/rate/access controls therefore apply equally to both rule-based and mini-model speakers. Contextual pet memories never leave the phone through this relay, although a voluntarily exported world JSON contains the summaries.

## Security, QA and rollout
1. Source syntax + Node regression (validation, foreground/no AI, simulated fallback, no XP, one-sentence output, memory day rollover, yesterday recall, memory clearing, no transcript in JSON, source policy).
2. Ephemeral Docker-backed private-server integration with real WSS, two authenticated room leases, legitimate sentence delivery, absent transcript in room snapshots, forged-session rejection, and account/block authorization. No production server mutations during CI.
3. Android unsigned PR builds and pinned package/signature checks for all three v32 identities; no overwriting v31 signer keys or local state. **Do not merge/sign/publish until CI and independent review are clean.**
4. Only after source gates and the owner's authorization, separately back up the existing home server and deploy the code with `TRIALUM_PLAYGROUND_AI_ENABLED=false`; verify current services and privacy first, then enable the relay for a controlled test. Existing server and Caddy ports remain unchanged.
5. Owner installs and manually tests all three v32 signed APK variants against the upgraded server: AI ON vs OFF, one/two pets, two owners (one without a model), fast replies, app background/tab change, disconnected WebSocket, blocked friend, resume and old JSON backup.
6. **Content quality/safety is not certified:** the tiny English-leaning LLM may repeat, hallucinate or produce unsuitable replies. It needs independent multilingual, prompt-injection and child-safety review before any public deployment.

**Rollback:** turn `TRIALUM_PLAYGROUND_AI_ENABLED=false` and redeploy the existing API service only. Clients revert to the same rule-driven simulated conversations, retaining their pets, scores, signer keys and local model files.

**Scope distinction:** this is the owner-requested playground-only mini-model relay. The broader future T17 (visits, richer autonomous social cognition, durable relationships, full content moderation) is not part of this change.
