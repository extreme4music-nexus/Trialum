# TRIALUM 1.5.6-B — private two-phone acceptance over HTTPS

Status: **owner execution required**. Android/server CI passed; real-world acceptance has NOT yet passed. This document is deliberately non-destructive and preserves the Ubuntu home NAS, router WireGuard, Webmin and existing Readarr port.

## Why private Tailscale Serve before public Funnel

Tailscale **Serve** provides valid HTTPS under a `*.ts.net` address restricted to participating devices in the user's tailnet. It can reverse-proxy to local `127.0.0.1:8687` with no router port forwarding. **Funnel is public**; do not use Funnel for initial acceptance or while edge abuse controls and safety review remain outstanding. Serve can be used only after installing Tailscale on Ubuntu and enrolling the two test phones in that private tailnet (existing router WireGuard is independent and need not be removed).

Official documentation: https://tailscale.com/docs/reference/tailscale-cli/serve and https://tailscale.com/docs/features/tailscale-serve

## Step 1 — synchronize source, keep private settings

- GitHub Desktop: Fetch/Pull `main`; do not copy tracked repo files onto private server before preserving server-local `.env` and any custom NAS configuration.
- Transfer only updated `server/` project files to `/opt/trialum/server`, **preserving** the current secret `.env`. Keep `TRIALUM_HOST_PORT=8687` and leave `TRIALUM_SOCIAL_ENABLED=false` initially.
- Before migration, verify `curl -fsS http://127.0.0.1:8687/healthz`; if not healthy do NOT proceed.

## Step 2 — protected database backup before first migration

```sh
cd /opt/trialum/server
umask 077
mkdir -p /root/trialum-db-backups
docker compose exec -T trialum-db pg_dump -U trialum -d trialum_social -Fc > /root/trialum-db-backups/trialum-pre-b.dump
test -s /root/trialum-db-backups/trialum-pre-b.dump
```

Keep this copy local, with root-only permissions. Later rehearse restore in a separate test database. Never paste DB credentials in chats, shell history, support tickets or Git commits.

## Step 3 — apply separate least-privilege role on existing volume

Set a **third, new, distinct** random secret, e.g. by `openssl rand -hex 32`, into private `.env`:

```ini
TRIALUM_HOST_PORT=8687
TRIALUM_SOCIAL_ENABLED=false
TRIALUM_APP_PASSWORD=GENERATE_A_PRIVATE_NEW_RANDOM_SECRET
```

Retain `PG_PASSWORD` and `TRIALUM_HEALTH_PASSWORD` unchanged; `chmod 600 .env` and validate:

```sh
docker compose config --quiet
docker compose up -d --build
docker compose exec -T trialum-db sh /docker-entrypoint-initdb.d/003_social_role.sh
docker compose exec -T trialum-db psql -U trialum -d trialum_social -tAc "SELECT EXISTS (SELECT 1 FROM pg_roles WHERE rolname='trialum_app')"
curl -fsS http://127.0.0.1:8687/healthz
curl -fsS http://127.0.0.1:8687/v1/meta
```

Expect `t`, healthy DB and `liveSocialEnabled:false`. Do not use `docker compose down -v` (would delete game DB). See also `V1.5.6_B_SERVER_MIGRATION.md`.

## Step 4 — PRIVATE test HTTPS

**Only after Stage 3 is healthy**, review which devices can access the Tailscale tailnet and enable Tailscale HTTPS/MagicDNS. If Tailscale is not installed, follow its official Debian/Ubuntu installation docs; **do not use a public Funnel** for this step. Test Tailscale Serve initially against the disabled health API:

```sh
tailscale status
sudo tailscale serve --bg 8687
tailscale serve status
```

This should return `https://<device>.<tailnet>.ts.net`, accessible **only to tailnet members**. Check `https://<device>.<tailnet>.ts.net/healthz` from another enrolled device. Don't publish the URL as a service to the general internet. Do not expose Webmin via Serve or Funnel.

When ready for a two-account test only, set `TRIALUM_SOCIAL_ENABLED=true` in private `.env`, then `docker compose up -d --no-deps --force-recreate trialum-api`. Verify `/v1/social/status` via your private HTTPS address. Confirm `tailscale funnel status` shows **nothing publicly active**.

## Step 5 — build Android debug APK for the exact private URL

The Android Social API URL is a **build-time** Gradle property; it is deliberately not editable to arbitrary HTTP endpoints by a game player. In GitHub repository Settings → Secrets and variables → Actions → Variables, set `TRIALUM_SOCIAL_API_URL` to the exact private `https://<device>.<tailnet>.ts.net` origin, with no path or trailing slash. This is a **public build variable** and must NOT include passwords, tokens or any secret. Use the Android debug build workflow on `main`; install only the resulting TEST APK on two phones enrolled in your Tailscale network. Make a local JSON backup of each test world's save first. If GitHub secrets or .ts.net origin change, rebuild the APK.

## Step 6 — two actual devices

- Device A: launch TRIALUM, enter Friends, create pseudonymous identity, tap Invite and share the HTTPS link.
- Device B: open it from a messaging app, tap **Open TRIALUM**, see A's nickname, explicitly accept. Reload friend list on A. Confirm it is mutual.
- Retry same code on a third account: must be rejected. Cancel new invite: cancelled link must fail. Self-invite and expired invite must fail. Block A/B then retry pairing: rejected.
- Test with network removed: solo game works, no fake friend acceptance. Test with B app in background: invitation should be retained for later processing, not silently auto-accepted.
- Nearby: on A host (new one-time invite) and on B scan. Approve runtime Bluetooth/Nearby permissions ONLY when prompted, compare **the same authentication digits on both screens**, explicitly approve both sides, verify invite preview and consent. Also test reject, mismatched digits, denial of runtime permissions, app background/stop.
- Confirm no social credentials in JSON export or local backup, no Webmin exposure and no network requests from players that never opted in.
- Capture relevant error codes/screenshots with all tokens and private secrets redacted. Visual and battery use on Galaxy-class device require user validation.

## Step 7 — turn test features back off

In server private `.env`, set `TRIALUM_SOCIAL_ENABLED=false` and recreate API, then disable private Serve if not required:

```sh
docker compose up -d --no-deps --force-recreate trialum-api
sudo tailscale serve --https=443 off
```

Confirm `tailscale serve status`, `tailscale funnel status` and `curl -fsS http://127.0.0.1:8687/healthz`. **Never enable Funnel during private tests.** After all B gates are checked by the owner, the public Funnel / domain / cloud rollout can be reviewed separately.
