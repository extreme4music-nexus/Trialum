# TRIALUM 1.5.6-E — Private messages and opt-in push (source beta)

**Scope:** authenticated friend-only message cards and finite-lifetime game event cards. **Not** a global/public chat. Not a shipped Play Store feature or a claim that a real Firebase device has been verified.

## In-game experience

- Open **Повеќе → 💌 Пораки** after voluntarily creating a social profile and connecting to the HTTPS server. Offline solo worlds never contact this endpoint unless selected.
- Send one of eight preset Macedonian friend phrases. No photo upload, audio chat, file attachment, external links, contact discovery, name/phone/email collection, public feed, presence/last-seen status or advertisements.
- Optional custom messages are implemented with 120 **Unicode characters**, basic contact/link/control-character blocking and encrypted storage, **but disabled by default** via `TRIALUM_FREE_TEXT_ENABLED=false`. Minor-safe review is mandatory before changing it; do NOT claim a word filter is full moderation.
- Inbox shows only accepted friends' cards, sent/read status, group invitations, arrivals/departures and cooperative upgrades. Users can read, delete for their own view, report (`spam`, `bullying`, `unsafe`, `other`) and mute a friend's **push notifications**, or block/remove them entirely in **Пријатели**.
- Reading a message does not disclose typing/presence; no tracking of opened notifications. No social cards or tokens in the offline save/JSON export.
- Event-specific WebSocket updates help active clients; the inbox refreshes **only while its screen is open** and on an explicit refresh. This is not a background WebSocket strategy.

## Server contract

Routes under `/v1/messages/`: authenticated `GET status`, `GET inbox`, `POST send` (preset or gated text + UUID idempotency key), `POST cards/:id/read`, `POST cards/:id/report`, `DELETE cards/:id`, `POST events/:id/read`, `DELETE events/:id`, `POST/DELETE mutes/:friendId`, and `GET/POST/DELETE push`.

- All calls require installation Bearer credential and allow only Android's packaged WebView origin; no URL credentials.
- Sending verifies active friendship without either-side block, under the same PostgreSQL pair advisory lock as blocking/removing. Per-sender and per-friend limits, pending-inbox cap, single-use UUID event key; client XP and balances are irrelevant.
- Presets store only the whitelisted phrase ID. For approved future custom messages the **AES-256-GCM** ciphertext, random IV and auth tag are stored in PostgreSQL, with a separate HKDF-derived key. Firebase device token ciphertext uses another derived key, never a plain token column; token is never sent back to clients, logs or JSON exports.
- New tables `message_cards`, `event_cards`, `friend_mutes`, `message_reports`; existing dormant `short_messages` **still has no app-role grant**, to avoid plaintext leakage. `push_registrations` is used only after explicit opt-in.
- Message/event cards expire after **7 days at most**, with hourly sweeper; reports metadata expire after 30 days. Read status remains until card deletion/expiry. Remove/block cleans both directions and related event cards, as do account-deletion FKs.
- Do not claim end-to-end encryption: the server decrypts message content to deliver it to the authenticated receiver. Backup media must be separately encrypted and retained narrowly.
- App user cannot self-configure arbitrary servers. API OFF by default and remains loopback-published on Ubuntu.

## FCM Android

- Android Firebase Messaging **only** (no Analytics/Crashlytics/Ads dependencies intentionally added).
- Firebase client project identifiers and exact authorized HTTPS API origin are optional build-time public variables. App includes no service account or push credentials.
- SDK auto-token registration and Firebase Analytics collection are disabled by manifest; the client initializes Firebase when user taps the consent control, asks Android 13+ permission, obtains FCM token, registers via native HTTPS, and stores only cipher at rest on server. Background token rotation syncs to server while consent is active. Account deletion or user opt-out disables local notifications and removes registration, with retry on connectivity failure.
- Generic **data-only** FCM body: `{kind:"trialum_event",reference:"<UUID>"}`. No private messages, pet names, statistics, friend name, URLs, offer links or analytics payload. Native handler shows only a generic title. Tapping opens the game; the user reads contents after authenticated inbox retrieval.
- Firebase/Google processes device/installation identifiers as a **service provider**. Update privacy policy and Play Data Safety declarations honestly; this is not literally zero external processing.
- No FCM is sent from CI. Real FCM receipt, rotation, offline queue, Android 13–17 permission/opt-out, OEM battery settings and exact device identity must be verified on two real Android phones.
