## Source of truth / no duplicated inventory

- Original Trialum engine remains the ONLY authority for food, pet actions, biomasses, molecules, game time, crafting and feeding. Original world state: `s.foodFactory.stock[recipeId]`, dynamic `E.foodRecipes`, and validated `E.craftFood(s,recipeId)` / `E.feedPrepared(s,petId,recipeId)`.
- NEW same-save `s.foodFactory.warehouseBins[recipeId]` stores **placement only** (`rack`, `cold`, `packing`, `hand`). This is not a currency or second inventory. The sum is reconciled against original `s.foodFactory.stock[recipeId]` on every projection/transaction; changing inventory elsewhere never creates or destroys portions, and new crafting gains default to the rack. Older backups without `warehouseBins` show all existing portions on the rack. Every action takes/puts EXACTLY ONE existing portion; no negative or forged IDs/zones, no double spend.
- `js/warehouse-inventory.js` pure model (UMD) implements `project(s,E.foodRecipes)`, `action(s, E.foodRecipes, {op,recipe,from,to})`. Only the existing parent game `js/app.js:TrialumLWBridge.warehouseOperation` may mutate placements, and on success calls original `notice`/render/scheduleSave/backup/sync, never local scene storage.
- `js/lw-d-interface.js` original same-origin strict iframe source bridge accepts only `trialum:lw:warehouse` with `op=take|put`, delegates to parent `warehouseOperation`, posts ack and new authoritative snapshot. Craft/feed use the already-existing original secure `trialum:lw:food` path. No writes to `localStorage`, `indexedDB`, FCM, networking, pets or world economy in Three renderer.
- `prototypes/lw-d/live-context.js` preserves actual existing mint/cyan holographic right HUD and LEFT dock. Adds real recipe names/stock by bin, select and confirm `Земи / Остави / Произведи / Нахрани`, with true eligibility and serial pending guard. Underlying Classic/LW actions in other rooms are not silently enabled while warehouse is active. All source stats projected from `world.food`.
- `agro-scene-bridge.js` carries only sanitized recipe ID/name/counts into nested renderer. Rendering CANNOT grant food. Original top resources remain unchanged.
