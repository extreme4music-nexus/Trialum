# Trialum Agro S6 — ONE FOOD SUPPLY CHAIN, owner directive 2026-11-16

**Order of authority:** existing **Food Laboratory** manufactures using original E.craftFood rules → existing **Warehouse** physically stores on racks, Cold Storage and Packing (plus temporary hand) → each original **pet** has its own food reserve at home and consumes exclusively those portions. When empty, player MUST resupply from warehouse. This is NOT a new food currency or second game engine.

## Grounded integration
- Exactly one canonical conserved amount per recipe: `s.foodFactory.stock[recipeId]`, unchanged format and original recipes/production.
- S5 saved placement `s.foodFactory.warehouseBins[recipeId]={rack,cold,packing,hand}` reused, no duplicated storage.
- S6 saved `s.foodFactory.petReserves[petId][recipeId]=amount`; pet ID, not habitat ID, so individual supplies remain separate even if multiple pets live together or a pet moves to a different home.
- **Invariant** for each recipe: `stock=warehouseBins.rack+cold+packing+hand+ΣpetReserves`. No separate pet/warehouse global stock amounts. Corrupt legacy over-allocation is reconciled without duplicating portions; a newly manufactured portion is attributed to rack. Old JSON saves without the new object remain valid and show existing food on racks.
- Original `E.craftFood` (including longplay invented recipes) creates genuine stock and spends original resources/action. The lab no longer has buttons to feed a pet. Current 3D Lab food analysis is read-only and synthesis is production-only.
- S6 `js/food-supply-chain.js` loaded AFTER original `js/longplay.js`: wraps both `E.feedPrepared` and generic `E.petCare(..., "feed")` so BOTH use **the selected pet's own reserve**. Prepared feeding keeps original species compatibility, pet action limits, boost and original engine. Basic feeding spends one already manufactured portion rather than deducting a SECOND 3 biomass. Failed feeding never consumes or sends new food. Otherwise all other care is untouched.
- Pure deterministic `js/warehouse-inventory.js`: `project`, `transferPet`, `hasPetPortion`, `consumePetPortion`; max five portions per confirmed transfer and no stock mutation on transfer. Pet supply accepted only for owned pet IDs, existing home and compatible recipe. No cross-pet food stealing.
- Existing pet Home panel `js/food-home-ui.js` displays own reserve by recipe, from-zone warehouse availability, manual +1 supply, return to warehouse and feed a portion. The basic "Нахрани" button also requires available own food. Guests/away pets cannot be resupplied through the Home UI.
- Original trusted parent `js/app.js:TrialumLWBridge.warehouseOperation` delegates `take,put,supply,return` only to this inventory model and original `notice` auto-save/backup/render. `js/lw-d-interface.js` accepts same-origin commands from exact existing 3D iframe. No direct `postMessage` to mutate state from warehouse child.
- Existing right cyan holographic `prototypes/lw-d/live-context.js`: live available warehouse counts separately from the pet-reserved portion totals; reserve supply/return confirmations for selected original pet, and authentic rack/cold/packing readouts. The GLB room itself remains read-only and receives only stock projections from original parent, not an invented economy.
- No server, cloud database, new accounts, advertising or changes to social APIs. Same original IndexedDB/localStorage fallback, JSON backups and engine validation. Partial migration never requires resetting an older save.
- No change to previously accepted S4/S5 visual architecture/animations: center main sliding door to Atrium, two solid-roof attached subrooms, autonomous miniature carriers/conveyors, original HUD and original navigation preserved.
- Later full 3D pet homes will use the SAME supply chain; S6 does not fabricate new pet-house GLBs or replace the legacy Home renderer.
