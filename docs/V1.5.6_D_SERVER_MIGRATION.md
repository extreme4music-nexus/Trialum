# 1.5.6-D — existing Ubuntu NAS PostgreSQL migration

**Never run `docker compose down -v` on the home server.** These are manual owner steps, not a deployment completed by GitHub.

1. In GitHub Desktop, Fetch/Pull **main only after D is merged and CI passes**. Copy new server files to `/opt/trialum/server`, keeping the existing root-only private `.env` unchanged. Host port stays **8687**; container port stays 8787; no need to change Readarr, Webmin, WireGuard or router rules.
2. Private backup (do not upload into Git/chat):

```sh
cd /opt/trialum/server
umask 077
mkdir -p /root/trialum-db-backups
docker compose exec -T trialum-db pg_dump -U trialum -d trialum_social -Fc > /root/trialum-db-backups/trialum-before-D.dump
test -s /root/trialum-db-backups/trialum-before-D.dump && echo "Backup OK"
```

3. Add only these private `.env` lines after confirming B and its app role are installed (preserve existing passwords exactly; do not share them):

```ini
TRIALUM_HOST_PORT=8687
TRIALUM_SHARED_ENABLED=false
```

4. Update containers without deleting their data volume, then apply the idempotent migration explicitly — PostgreSQL does **not** replay init scripts on an existing volume:

```sh
cd /opt/trialum/server
docker compose config --quiet
docker compose up -d --build
docker compose exec -T trialum-db sh /docker-entrypoint-initdb.d/004_shared_playgrounds.sh
docker compose exec -T trialum-db psql -U trialum -d trialum_social -tAc "SELECT to_regclass('public.shared_playground_state') IS NOT NULL;"
docker compose exec -T trialum-db psql -U trialum -d trialum_social -tAc "SELECT to_regclass('public.playground_invites') IS NOT NULL;"
curl -fsS http://127.0.0.1:8687/healthz
curl -fsS http://127.0.0.1:8687/v1/meta
```

Both SQL checks must print `t`, health `db:connected`, and metadata must still say `sharedPlaygroundEnabled:false`.

5. **Do not turn on D publicly.** After a reviewed private HTTPS/Tailscale Serve test address and two test Android APKs built with `TRIALUM_SOCIAL_API_URL`, temporarily set both `TRIALUM_SOCIAL_ENABLED=true` and `TRIALUM_SHARED_ENABLED=true` in private `.env`; then:

```sh
docker compose up -d --no-deps --force-recreate trialum-api
curl -fsS http://127.0.0.1:8687/v1/meta
```

Run the owner two-phone script from D documentation. Switch both feature flags off again and recreate API after private tests. Keep the host port bound to `127.0.0.1`. **Tailscale Serve is tailnet-private; Funnel is public**; do not use Funnel for these acceptance tests.

6. Confirm app DB role can read D tables but **cannot** read E's `short_messages` or `push_registrations`. This separation is validated automatically in CI. If migration fails, leave D disabled and restore from the local backup only after diagnosing the failure. Never paste `.env` or database dumps into chats.
