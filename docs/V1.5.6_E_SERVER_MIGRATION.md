## Step 1 — stop if B/D migrations are not already accepted

The existing PostgreSQL volume **never reruns** /docker-entrypoint-initdb.d scripts. B's `003_social_role.sh`, D's `004_shared_playgrounds.sh` and E's `005_messages_push.sh` must all be applied in order after a verified local backup. Complete private HTTPS and two-device verification for B/D; source CI alone is not deployment approval.

```bash
cd /opt/trialum/server

umask 077

docker compose exec -T trialum-db pg_dump -U trialum -d trialum_social -Fc > /root/trialum-db-backups/trialum-before-E.dump
test -s /root/trialum-db-backups/trialum-before-E.dump && echo "Database backup created"
```

Practice restoring backup to a **separate** test database, not on live. Keep no secrets in Git or chat. Privately preserve `.env` before syncing `server/` from `main`.

## Step 4 — FCM setup is SEPARATE and explicitly optional

Only after E messaging passes private testing:

1. Create a Firebase project with Cloud Messaging API enabled, matching package `com.trialum.ziivaiskra`. Firebase has no required Analytics SDK dependency in TRIALUM. Retrieve **PUBLIC** client identifiers: Application ID (`1:...:android:...`), sender ID, project ID, Web API key. No service-account JSON in GitHub Actions or APK.
2. GitHub → repository Settings → Secrets and variables → Actions → **Variables**, set:
   `TRIALUM_SOCIAL_API_URL` (exact private `https://...ts.net`), `TRIALUM_FIREBASE_APP_ID`, `TRIALUM_FIREBASE_SENDER_ID`, `TRIALUM_FIREBASE_PROJECT_ID`, `TRIALUM_FIREBASE_API_KEY`. Trigger a new debug APK build; test with two devices on same private tailnet. Config is baked in at build time. Firebase project/client keys are public identifiers, but restrict API keys appropriately and never publish service-account credentials.
3. Create a **dedicated minimally privileged** FCM HTTP v1 sender service account (Firebase Cloud Messaging messaging-send permissions only). Store its JSON with restrictive file permissions outside the Git repository in a private Ubuntu directory, e.g. `/opt/trialum/private/fcm-service-account.json`. The container must be able to read it through a **read-only** mount and no other services may access it. Never commit, log, paste or upload this file.
4. In private `.env` set the exact FCM project ID and `TRIALUM_FCM_SERVICE_ACCOUNT_PATH` to the absolute host file path. Confirm the secret is present and only then set `TRIALUM_PUSH_ENABLED=true`. Run the optional, separate overlay:

```bash
cd /opt/trialum/server
docker compose -f compose.yaml -f compose.push.yaml config --quiet
docker compose -f compose.yaml -f compose.push.yaml up -d --build
```

FCM sends **data-only generic event references**, never text or pet stats. Android requires its own opt-in per device and notification permission on Android 13+. Users who decline still receive inbox messages when they open the game; no hidden background registration.

If no Firebase project is connected, **leave push disabled** and use private message cards. App should display “FCM не е конфигуриран”, not claim that push works.

## Step 5 — revocation and rollback

Set `TRIALUM_PUSH_ENABLED=false`, `TRIALUM_MESSAGES_ENABLED=false` and restart only the API with the normal compose file if needed. Never delete database volumes. Check `/healthz` still reports healthy, and ensure `tailscale funnel status` shows no publicly enabled server. Account deletion cascades all message and push registrations; individual push opt-out unregisters and permanently disables local display, with retry of registration deletion if the server was offline.
