# Android патека: од HTML до APK

`android-template/` содржи почетен Android Studio Kotlin проект со истиот HTML/CSS/JS играчки код. Тој е **изворен шаблон — не е компајлиран APK**.

## Важни практични детали

1. Наместо директно `file:///...` се користи `WebViewAssetLoader`, кој локално го сервира вградениот HTML преку сигурна внатрешна HTTPS адреса. Со тоа се намалуваат проблеми со file origin и локално складирање.
2. Зачувувањето останува IndexedDB на Android WebView. Бекапот JSON треба да се тестира и преку Android системскиот избор на датотеки.
3. Мостот `TrialumAndroid.updateState(...)` во `js/app.js` ја испраќа последната состојба на глад, радост, чистота и услови во живеалиштето до локален Android SharedPreferences snapshot. Тоа не е cloud sync.
4. `CareWorker` проверува приближна дневна потреба од последниот snapshot на шест часа со WorkManager. Тоа не е гарантирано точно време, бидејќи Android може да го одложи. Worker не ја извршува целата HTML еволуција додека играта е затворена; финалната еволуција се пресметува при следно отворање.
5. За Android 13+ е потребна дозвола POST_NOTIFICATIONS. Без дозвола нема системски нотификации. Уредот и режимите за штедење батерија може да влијаат.
6. За производство треба да се додадат апликациска икона во сите mipmap-големини, signing key, компатибилност со Android 17, повеќе тестови за IndexedDB/WebViewAssetLoader и проверка на ресурсите.

## Развојна процедура

1. Отвори го `android-template` во Android Studio (Android SDK 35 и соодветен Gradle се потребни).
2. При Gradle build задачата `syncWebAssets` ги копира коренските `index.html`, `js/`, `assets/`, `vendor/` во Android assets. За секоја измена на web играта повторно се пакува истиот извор.
3. Вклучи USB debugging, избери тест уред и Run. Не е тестирано на уред во овој пакет — очекувај дополнително прилагодување пред објавување.
4. Тестирај: хранење и нотификации, игра затворена 2+ дена, дозволи одбиени/одобрени, рестарт на уред, JSON бекап/увоз, смени на временска зона.

## Прагови (тековни)

- Ситост под 35% → глад.
- Радост под 35% → сака да игра.
- Чистота под 30% → треба миење.
- Квалитет на живеалиште под 58% → грижа за биосвет.
- Пренаселеност (биотовар над капацитет) → сигнал во самата игра.

Важно: native worker прави *прогноза* за состојбата, а не точна синхронизација на игровните дневни правила. За сигурна прецизност, Android 1.2 треба да користи заедничка логика или внимателно усогласена пресметка.
